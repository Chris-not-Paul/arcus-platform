# ARCUS Failure Learning Matrix v1

## Purpose

The Failure Learning Matrix is the auditable bridge between a fixed cohort of
comparable Italian bridge-collapse records and project-specific investigation
questions.

It implements a deliberately narrow form of learning from failures:

```text
official project-point exposure
-> cohort selected without reading collapse outcomes
-> documented outcomes summarized by process and component
-> repeatability and robustness gates
-> investigation question or explicit abstention
```

It does not estimate collapse probability, certify a bridge as safe or unsafe,
rank assets, calculate a normalized mitigation score or prescribe an
intervention.

## Versioned output

The backend response exposes:

```text
failure_learning_matrix.matrix_version = arcus-failure-learning-matrix-v1
```

The matrix is generated by
`buildHydraulicFailureLearningMatrix` in
`server/mitigationIntelligenceService.js` and is included in the Collapse
Intelligence UI, JSON evidence package and PDF report.

The response is part of `arcus-api-contract-v3`. A frontend receiving an older
payload must display `contract_unavailable`; it must not reinterpret the
missing matrix as an engineering abstention.

## Cohort contract

The cohort must be fixed before reading:

- `hydraulic_intelligence.failure_process`;
- `hydraulic_intelligence.component_involved`;
- `hydraulic_intelligence.evidence_level`.

This protects the output against choosing historical events because they
contain the desired outcome. The selected project-point hydraulic signature
supports comparability; it does not reconstruct historical hazard at the date
of collapse and does not prove causation.

## Evidence units

Each process row reports both event-level and independent-episode evidence:

- raw records;
- evidence-weighted records;
- independent episodes;
- episode-effective evidence;
- documented and probable records;
- affected-component breakdown;
- source count and auditable event identifiers.

Independent episodes are the primary protection against treating multiple
bridges affected by one event as independent repetitions.

## Row states

### `qualified_investigation_priority`

The process passes the process-specific independent-episode and effective
evidence thresholds and is robust across the required retrieval windows. The
matrix may expose a non-prescriptive investigation priority.

### `observed_below_qualification_threshold`

The process occurs in the fixed cohort but does not pass all qualification
gates. It remains visible as evidence, but no process-specific priority is
generated.

### `mechanism_unresolved`

The historical record does not resolve a hydraulic process. The row describes
an evidence gap and must never be interpreted as a mechanism.

## Matrix states

### `available`

At least one process-specific priority is supported. Rows below threshold
remain visible and clearly separated from qualified rows.

### `limited_evidence`

The cohort is usable but no process qualifies. Only the generic hydraulic and
geomorphological investigation priority is admissible.

### `abstained`

No matrix rows or strategies are generated. Typical causes include absence of
official hydraulic intersection at the project point or insufficient usable
evidence. Territorial nearby context is not converted into a project lesson.

## Geometry boundary

Bridge length and piers in the active riverbed are reported only after cohort
selection as descriptive context for the historical process rows.

Their production role is:

```text
post_retrieval_descriptive_evidence_only
```

They are not used for retrieval, qualification, scoring or causal inference.
The current geometry audit classifies their value as
`exploratory_signal_only`; see
`docs/ARCUS_HYDRAULIC_GEOMETRY_VALUE_AUDIT.md`.

User-declared material, structural type, crossing type and destination use may
reorder otherwise hazard-comparable analogues under Project Bridge Profile v1.
This does not change matrix thresholds. User-declared bridge length and piers
in the active riverbed remain descriptive; see
`docs/ARCUS_PROJECT_BRIDGE_PROFILE_V1.md`.

## Inventory-denominator boundary

The active Failure Learning Matrix does not use an infrastructure-inventory
denominator, a provincial collapse rate or Historical Collapse Incidence.
Historical failures are interpreted through declared analogue cohorts,
independent episodes, documented processes and evidence quality. This avoids
turning a current inventory snapshot and a multi-decade collapse record into a
false frequency or probability.

## Required interpretation

The strongest valid statement is:

> Comparable documented collapse episodes repeatedly involved this process;
> therefore this process supports a project-specific investigation question,
> subject to professional confirmation.

The matrix does not support statements that a similar bridge will collapse,
that one feature caused the historical failures, or that a proposed measure
will reduce risk by a quantified amount.

## Tests

The contract is covered by:

```text
npm run test:failure-learning-matrix
npm run test:mitigation-intelligence
npm run test:collapse-intelligence-report
```

The test suite covers qualified, limited-evidence and abstained states, the
fixed-cohort and geometry boundaries, UI/report presence and forbidden
interpretations.

Independent engineering validation is governed by
`docs/ARCUS_COLLAPSE_INTELLIGENCE_EXPERT_REVIEW_PROTOCOL.md`. Matrix thresholds
remain frozen while that protocol is awaiting human responses.
